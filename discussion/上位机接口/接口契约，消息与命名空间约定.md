# 哨兵上位机接口契约（M1 · v0.4 草案）

> 定位：本文档定义**执行层（底盘/云台控制器）与上位机各模块（遥控、视觉、导航、仲裁器）之间的消息、命名空间、坐标系与时序契约**。它是视觉/导航队友接入本系统的唯一依据。
> 文中所有话题与语义均**逐一核对源码**（`spr_sentry_controllers`、`spr_msgs`、`spr_remote_control`），非臆想；凡未定项一律列入「§7 开放项」。

---

## 1. 命名空间规则（已核实）

- **整车命名空间 `/sentry`**（v0.4 起）：`controller_manager`、控制器、`robot_state_publisher`、spawner 全部运行在 `/sentry` → 车的话题统一收进 `/sentry` 话题树。
- 控制器是独立节点，节点名 = 控制器名，位于 `/sentry` → 私有话题 `~/xxx` = `/sentry/gimbal_controller/xxx`、`/sentry/chassis_controller/xxx`。
- **两个刻意保留在全局根的例外**：
  - **TF**（`/tf`、`/tf_static`）留在全局根（rviz/导航等共享）；
  - **`pid_state` 诊断话题**由 `control_toolbox::PidROS` 强制以 `/` 开头建绝对话题（`/pitch/pid/pid_state` 等），忽略命名空间——库行为，无法收进 `/sentry`（属调试话题，靠过滤视图使用）。
- 上位机源节点（键盘/串口/视觉/导航/仲裁器）在全局发布，写**绝对名**：`/sentry/chassis_controller/cmd_vel`、`/sentry/gimbal_controller/gimbal_cmd`。

## 2. 运行时话题表（已核实）

| 话题 | 类型 | 方向 | QoS | 说明 |
|---|---|---|---|---|
| `/sentry/chassis_controller/cmd_vel` | `geometry_msgs/Twist` | chassis_controller **订阅** | `SystemDefaults` | 底盘速度指令。约定：`linear.x` 前、`linear.y` 左、`angular.z` 逆时针为正（见 `chassis_controller.cpp:194`） |
| `/sentry/gimbal_controller/gimbal_cmd` | `spr_msgs/GimbalCmd` | gimbal_controller **订阅** | `SystemDefaults` | 云台**唯一指令入口**：模式 + 三轴角度。`mode=2`(自瞄)与`mode=3`(遥控)的目标角均取本消息 `pitch_angle`/`small_yaw_angle`/`big_yaw_angle`（v0.3 已合并原 `ex_state_interface`） |
| `/sentry/gimbal_controller/gimbal_state` | `spr_msgs/GimbalState` | gimbal_controller **发布** | `SystemDefaults` | 云台状态反馈：当前模式、是否在跟踪、三轴目标角 ref、三轴电流 ref（实时双缓冲发布） |
| TF `odom → base_footprint` | `geometry_msgs/TransformStamped` | chassis_controller 发布 | — | 轮速积分里程计位姿。**注意：仅发 TF，当前不发布 `nav_msgs/Odometry` 消息**（见 Q2） |
| `/sentry/joint_states` | `sensor_msgs/JointState` | `joint_state_broadcaster` 发布 | — | 全关节状态 |
| `/pitch/pid/pid_state` 等 7 个 | `control_msgs/PidState` | PidROS **发布**(例外) | — | control_toolbox 强制绝对根，不进 `/sentry`（见 §1）；调 PID 波形时用 |

## 3. 消息与语义

### 3.1 `spr_msgs/GimbalCmd`

```text
uint8   mode           # 0保持 1扫描 2自瞄 3遥控
float64 pitch_angle    # 云台 pitch 目标角 (rad)
float64 small_yaw_angle
float64 big_yaw_angle
```

模式语义（源码 `gimbal_controller.cpp` update 主逻辑）：

| mode | 含义 | 目标角来源 |
|---|---|---|
| 0 | 保持不动 | 目标 = 当前反馈 |
| 1 | 扫描 | 时间驱动三角波扫 pitch/yaw（斜坡限速+软限位），纯扫描 |
| 2 | 自瞄 | 目标角 = 本消息 `pitch_angle`/`small_yaw_angle`（视觉目标角）；**信号超时自动回落扫描**（看门狗 `aim_timeout`，默认 0.2s） |
| 3 | 遥控 | 目标角 = 本消息三轴角度（绝对关节角） |

> ⚠️ **v0.3 变更**：原 `ex_state_interface`（自瞄目标角入口）已合并进 `gimbal_cmd`——`mode=2` 直接读本消息角度字段。视觉有目标→发 `mode=2`+角度；无目标→发 `mode=1` 或停发（控制器超时兜底回扫描）。

### 3.2 `spr_msgs/GimbalState`（双用途！）

```text
std_msgs/Header header
uint8   mode
bool    is_tracking
float64 pitch_angle_ref        # 目标/反馈：pitch 目标角
float64 small_yaw_angle_ref    # 目标/反馈：small_yaw 目标角
float64 big_yaw_angle_ref
float64 pitch_current_ref      # 位置环输出的电流/力矩参考
float64 small_yaw_current_ref
float64 big_yaw_current_ref
```

**v0.3 起该消息仅作状态输出**（原“自瞄目标输入”用途已合并进 `gimbal_cmd`）：

- **输出**（`/sentry/gimbal_controller/gimbal_state`）：控制器填好全字段回传，供上位机监视当前模式/目标/电流。`is_tracking=true` 表示正处于自瞄跟踪（mode=2 信号未超时）。
- 自瞄实现见 `aim_mode()`：读 `gimbal_cmd` → `target_pitch_/target_yaw_` → 位置 PID。代码已留 **目标角速度前馈 TODO**（当前无角速度字段，见 Q5）。

### 3.3 输入源与模式（v0.3：各源发 mode，控制器做安全兜底）

**现状（v0.3 合并后）**：控制器只收 `gimbal_cmd` 一条指令。各输入源用 `mode` 表达意图：

| 输入源 | 有目标 | 无目标 |
|---|---|---|
| 视觉（比赛） | `mode=2` + 目标角 | `mode=1`（扫描），或停发由控制器超时回落 |
| 键盘/遥控（调试，0/1/2/3 键切） | `mode=3` + 手动角度（切 `2` 时用角度键喂“假目标”） | `mode=1` |
| 保持 | `mode=0` | — |

**控制器内置安全兜底**：`mode=2` 自瞄期间，距上次收到 `mode=2` 指令超过 `aim_timeout`(默认 0.2s) → **自动回落扫描**（视觉丢目标不失控）。

**仍待 M2**：多源**同时**在线时的优先级/抢占（遥控>自瞄>导航）与指令整形，由 `spr_cmd_arbiter` 负责——届时输入源对仲裁器表达意图、仲裁器输出最终 `gimbal_cmd`。

## 4. 坐标系与 TF 约定

| Frame | 说明 |
|---|---|
| `odom` | 世界/里程计系，由 chassis 轮速积分（原点即开机位） |
| `base_footprint` | 车体系：x 前、y 左、z 上（与 `/sentry/chassis_controller/cmd_vel` 约定一致） |
| 云台关节 | `pitch_joint` / `small_yaw_joint` / `bigyaw_joint` 为**关节角**（相对各自零位），非世界系角度 |

**待对齐**：视觉解算出的目标角是“相对哪个系”？当前 `aim_mode()` 直接把 `gimbal_cmd.small_yaw_angle` 当**云台关节目标角**用。若视觉给出的是相机/云台系下的偏差，需约定换算责任在谁（见 Q1）。

## 5. 时序与健康度

| 信号 | 建议频率 | 现状 |
|---|---|---|
| `/sentry/chassis_controller/cmd_vel`（遥控） | ≥ 20 Hz 持续 | 键盘 20 Hz 持续 ✓ |
| `/sentry/gimbal_controller/gimbal_cmd` | ≥ 20 Hz 持续 | 键盘 20 Hz 持续 ✓ |
| 自瞄目标信号（`mode=2` 指令） | 100–500 Hz | **无源**（视觉未接入）；控制器看门狗 `aim_timeout=0.2s` 已内置 ✓ |
| 超时/失活语义 | — | 控制器：自瞄信号超时→回落扫描（已实现）；多源失活归零→仲裁器（M2） |

## 6. 目标拓扑（M2 仲裁器落地后）

```text
遥控/键盘 ──► spr_cmd_arbiter ──► /sentry/chassis_controller/cmd_vel ──► chassis_controller
视觉(自瞄) ─► (仲裁+整形+急停)  ─► /sentry/gimbal_controller/gimbal_cmd ─► gimbal_controller
导航(巡逻) ─►                        └──► 源超时归零 / 遥控最高优先级
```

控制器只保留单一输入，多源合并与模式裁决全部收敛到仲裁器（详见后续 M2 设计文档）。
